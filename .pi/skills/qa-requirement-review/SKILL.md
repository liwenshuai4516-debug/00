# 需求评审

<!-- 参考路径相对于本技能目录，不是当前工作目录。 -->
1. 使用 read 读取本技能目录下的 references/checklist.md。
2. 依据用户提供的需求正文或指定文件进行评审；没有需求内容时先询问，不推测业务规则。
3. 对照检查清单审查，仅报告有原文依据的问题；需求未规定的行为列为待确认项。

<!-- 建议需要单独标注，不能当作原文已规定的业务规则。 -->
4. 每项结果包含：需求原文或文件位置、发现的问题、问题影响、建议补充的验收条件。明确区分“原文已规定”“待确认项”和“建议补充”。
5. 仅输出评审结果；需要修改文件时按用户要求执行。没有实际执行证据时，不宣称测试通过。
