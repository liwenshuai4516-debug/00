# 准备工作区测试数据目录

作为测试工作流的前置步骤，准备当前工作区中的 `qa/data/`，用于后续保存 JSON、CSV 等测试输入文件。只创建必要目录并验证可用性，不生成业务数据，不启动浏览器或测试，不修改应用配置。

本技能在被调用时执行；应用启动、工作区恢复或切换后需要由宿主或工作流再次调用，不能把技能文件当作自动事件监听器。

## 输入与工作区来源

- 从宿主提供的当前会话上下文获取实际绑定的工作区绝对路径。Pi 中使用宿主注入的会话 cwd；只有宿主明确将工具 cwd 绑定到当前会话时，才可使用该 cwd。
- 可接收上游 `expectedWorkspaceRoot`，表示本任务预期的工作区，用于与当前绑定核对，不能用它覆盖当前工作区。
- 不以聊天中出现的路径、技能所在目录、应用安装目录、Git 根目录或任意终端的 `pwd` 推断用户已选择工作区。不读取 `.env`、认证或真实历史来猜测绑定。
- 无法取得可信绑定时返回 `blocked / workspace-unavailable`，提示选择工作区或由宿主补充上下文；不先在其他目录创建文件。

## 执行

1. 读取当前工作区适用的 `AGENTS.md` 等项目约束，遵守现有工具权限。使用可用的原生文件或 bash 工具操作，不要求宿主增加专用工具或更改 Pi 的工具登记。
2. 将工作区路径解析为真实路径，确认存在且为目录。若提供 `expectedWorkspaceRoot`，同样解析并核对；不一致时返回 `blocked / workspace-mismatch`，不写入任一目录。
3. 目标固定为真实工作区下的 `qa/data/`。逐级检查 `qa`、`data`：已存在的普通目录直接复用；符号链接必须解析为工作区内的目录，否则停止；同名文件、悬空链接或越界返回 `failed`。路径包含空格、中文或引号时使用参数传递或正确引用，不能把路径拼成可执行代码。
4. 只创建缺失的目录，先检查父目录再创建子目录，创建后重新解析并核对仍在真实工作区内。并发创建遇到目录已存在时重新检查，不覆盖已有内容。边界检查只约束本次自动初始化，不改变 Pi 原生工具的其他访问能力，也不宣称可抵御其他进程并发替换路径。
5. 在目标目录内用随机文件名排他创建一个空的写入探针，随后删除并确认清理。只有目录检查、实际写入和探针清理全部成功才返回 `ready`。不修改已有数据来测试写入能力。
6. 返回下面的结构化结果。创建或探针失败时保留已有数据，不自动换位置、改权限、修改忽略规则或清理目录；本次已创建的空目录可以保留，在结果中列出。修复原因后可以重新调用，不盲目循环重试。

文件操作报错或所需工具不可用时返回 `failed`，保留实际错误原因。初始化失败只阻止依赖数据目录的后续步骤，不要求关闭会话或撤销已完成的工作区切换。

## 输出契约

将实际工具结果整理成一个 JSON 对象交给上游。这里约定的是 Agent 交接格式，不代表宿主已经提供同名 API 或自动路由能力。

```json
{
  "status": "ready",
  "workspaceRoot": "/absolute/workspace",
  "dataDir": "/absolute/workspace/qa/data",
  "directoryAction": "created",
  "createdDirectories": ["/absolute/workspace/qa", "/absolute/workspace/qa/data"],
  "reason": null,
  "message": "测试数据目录已准备完成。",
  "cleanupPending": []
}
```

- `status`：`ready` 表示本次检查通过；`blocked` 表示缺少可信工作区或与任务预期不符；`failed` 表示目录验证或文件操作失败。
- `workspaceRoot`：实际确认的真实绝对路径；无法确认时为 `null`。
- `dataDir`：仅在 `ready` 时提供已验证的真实绝对路径，其余为 `null`，避免后续步骤误用。
- `directoryAction`：成功新建最终数据目录为 `created`，成功复用为 `reused`；未就绪为 `null`。
- `createdDirectories`：只列本次实际创建的目录；无创建时为 `[]`，失败时也保留真实记录。
- `reason`：成功为 `null`；未就绪使用简短原因码，例如 `workspace-unavailable`、`workspace-mismatch`、`path-conflict`、`path-outside-workspace`、`io-error`、`tool-unavailable`、`probe-cleanup-failed`，具体原因写入 `message`，不输出敏感内容。
- `cleanupPending`：仅列本次探针未能删除的绝对路径；未生成探针或清理完成时为 `[]`。清理失败必须为 `failed`，不能声称目录就绪。

## 工作流交接

编排顺序：准备工作区 → 判断 `status` → 准备测试输入 → 后续测试步骤。

只有 `status === "ready"` 才向后传递 `workspaceRoot` 和 `dataDir`。后续步骤使用返回路径保存测试输入，不重新猜测目录；数据文件命名、是否允许覆盖由具体测试任务决定，本技能不授权覆盖。

工作区切换后，对新任务重新调用本技能，并以原任务工作区作为旧任务的预期绑定；不把旧结果改写为新目录，不迁移已有文件或运行产物。已启动任务保留原目录归属；无法保证绑定一致时暂停依赖写入，交由上游处理。

新项目 UI 工作流由 qa-ui-basic 使用当前工作区的 `qa/data/ui/cases/` 保存脚本和说明；具体项目匹配、登录及资产检查由其内置工具负责。既有 UI 脚本、录制和报告继续使用 `qa/ui/cases/`、`qa/ui/recordings/`、`qa/ui/runs/`，本技能不创建或迁移这些产物。密码、登录态、密钥不写入 `qa/data/`，沿用宿主已有私有存储与清理机制。

`ready` 只证明本次目录准备成功，不代表测试数据已生成、后续运行期间始终可写或任何测试通过。仅查看旧报告时无需调用本技能。
