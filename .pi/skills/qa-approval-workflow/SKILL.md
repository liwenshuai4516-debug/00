# 多角色审批流执行

## 适用与前置

只用于测试数据；真实业务数据需用户明确授权。
需要：记录名称或 id、详情页路由、各节点处理人账号（系统管理 → 用户管理）、登录密码（取项目配置或用户提供，不写入脚本、日志或报告）。

## 1. 登录与租户

- `/login` 只有用户名、密码两个输入框；提交后若进入 `/tenant/switch`，选「项目管理」并点「立即选择」。
- 每个账号使用独立 browser context，避免串号；临时 storageState 权限 0600，结束删除。
- 处理人姓名映射 username：用户管理页，或带 `x-client-code` 请求头请求 `/api/base-service/user/page?pageNum=1&pageSize=100`。列表可能分页或缺行；找不到时按拼音尝试并验证登录，不要猜密码。

## 2. 起点

- 创建并提交记录，捕获 initiate 响应里的 id；合同编号可能由后端自动生成（本次为 `HSKJ-JYHT-2026-004`）。
- 打开详情页 `.../OperationContractDetail?id=<id>` 读取当前「流程节点 / 处理人」。
- 不要用 `BusinessProcess?kind=...&id=...` 预览页判断权限：该页只读，可能没有审批按钮。

## 3. 逐节点审批（循环到终态）

1. 读详情页审批流程尾部，取当前节点和处理人。
2. 用该处理人账号登录、选租户、打开同一详情 URL。
3. 填「审核意见」，点「同意」；发起人确认等节点按页面按钮点「确认」。
4. 等待返回列表或提示，读取行状态，进入下一节点。
5. 记录节点、处理人、账号、意见、时间、结果。

节点特例：

- **发起人上传定稿**：上传合同定稿，填意见，点同意。
- **合同管理员盖章**：按普通节点同意。
- **发起人确认**：通常需要上传合同扫描件再确认；若上传接口 200 但组件不登记文件、点确认无请求，按页面缺陷记录并请用户手动完成，不能伪造通过。

## 4. 终态断言

- 列表行状态为「已完结 / 已完成」。
- 详情审批流程所有节点都显示处理人、处理意见、同意/确认和时间。
- 合同编号已生成、附件在详情可见。
- 不用“流程走到最后”代替终态断言；必须有列表或详情状态证据。

## 5. 失败处理

| 触发 | 处理 |
| --- | --- |
| 登录 401 / 停在 `/login` | 核对账号、密码、租户；用户管理确认账号状态 |
| 无「同意」按钮 | 账号不是当前处理人，或打开了 BusinessProcess 预览页；改用 OperationContractDetail |
| 点确认无请求、无提示 | 检查必填上传/意见；上传组件不登记文件按页面缺陷转人工 |
| 创建页审批人字段禁用 | 后台仍可能生成审批链；以详情页实际节点为准，并记录页面缺陷 |
| 待办中心为空但合同显示节点 | 直接按详情 URL 处理；待办任务生成异常单独记录 |

## 6. 输出

- 节点表：节点 / 处理人 / 账号 / 意见 / 时间 / 结果。
- 终态证据：列表状态、详情 URL、合同编号。
- 未覆盖项与页面缺陷，不把人工介入写成自动通过。
