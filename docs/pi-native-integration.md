# Pi 1.4.0 原生接入

资源与工具优先遵循固定版本的 [Pi SDK](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/sdk.md)。Electron 继续负责模型选择、会话绑定、输入保存和窗口交互。

## 启动与新建对话耗时

窗口出现后仍需准备会话：目录和状态读取、官方资源发现、项目信任、模型目录及认证检查、扩展 `session_start`，新建对话还必须等待旧扩展 `session_shutdown` 和设置保存。新会话创建失败时保留旧会话，不通过省略清理或超时销毁来提速。

模型运行时使用公开的 `ModelRuntime.create({ refreshOnCreate: false })`，登记后备地址和扩展供应商后统一离线刷新，减少登记前的一次完整目录检查。会话及输入绑定后，模型、上下文和侧栏展示读取并行执行；文件草稿与空会话列表共用互斥入口，保留其先后顺序。展示读取全部收尾后恢复发送；信息读取失败仍由各区域提示，输入继续按会话保存。

2026-11-03 隔离配置测量（未请求模型）：SDK 首次导入约 0.6～0.9 秒；加载当前安装包代码的首次会话约 0.7～0.9 秒，后续约 50 毫秒；`pi-chrome` 在没有浏览器连接时，旧会话清理仍等待约 2 秒。这解释了新建对话的部分等待，未完整复现使用者环境中的 5～10 秒。隔离配置不包含个人 MCP 服务、真实认证及聊天历史，不将此结果视为实际环境耗时保证。

主进程对超过 500 毫秒的准备步骤输出 `[Pi 会话准备]` 日志，分别标识目录与状态、资源发现（含信任）、模型目录与认证、会话与扩展启动；慢关闭输出 `[Pi 会话关闭]`。日志仅含固定步骤名与耗时，不含路径、凭据或消息。资源步骤也可能包含等待使用者信任决定，不能仅凭它耗时长就认定资源扫描慢。

回归入口：`node --test tests/unit/custom-providers.test.js tests/unit/pi-session-lifecycle.test.js`；`node_modules/.bin/electron tests/ui/session-readiness.check.cjs`。新检查在修改前分别复现重复模型刷新和串行读取；修复后检查并行读取、互斥顺序、准备期间禁止发送、信息失败恢复及输入归属。另有旧 `session-service.test.js` 中“缺少模型配置必须报错”的断言在修改前后均失败，当前模型配置已允许采用 Pi 官方设置，不据此修改本轮无关逻辑。

## 资源位置

运行入口使用官方 `getAgentDir()`：默认 `~/.pi/agent`，可由 `PI_CODING_AGENT_DIR` 指定。设置、信任记录和内置 MCP 使用同一目录。旧 `<userData>/pi-resources` 内容保留，未自动搬迁；已有资源需要放入所选的官方目录。

由 `SettingsManager.create` 和 `DefaultResourceLoader` 处理：

- 用户 `settings.json` 中的资源路径、过滤和 `packages`。
- 用户与受信任项目的技能、模板、扩展、主题。
- 个人和项目 `.agents/skills`，包括官方祖先目录及仓库边界规则。
- `SYSTEM.md`、`APPEND_SYSTEM.md` 与上下文文件。

技能保留官方独立 Markdown、便携 `SKILL.md` 目录与链接支持；参考文件、脚本和资产按实际 Pi 工具使用。警告、冲突与加载失败通过主进程诊断提示，名称冲突遵循官方先发现者保留规则。

### 手动查看资源来源

开发诊断脚本统一放在 `scripts/`。在要检查的工作目录执行 `node /项目绝对路径/scripts/inspect-pi-sources.mjs`；在本仓库根目录可直接执行 `node scripts/inspect-pi-sources.mjs`。脚本使用当前工作目录及官方 `getAgentDir()`（支持 `PI_CODING_AGENT_DIR`），输出技能、提示词模板、扩展的来源与配置范围，以及部分技能和扩展的路径示例。不创建聊天会话，也不请求模型。

该脚本仅供手动排查，不接入应用启动流程或 `npm test`。它以 `projectTrusted: false` 加载资源，不进行桌面项目信任询问，因此结果不等同于已信任项目的完整资源列表。官方 loader 的 `reload()` 会执行已启用扩展的工厂代码，不能视为纯静态文件读取；自动验证使用临时配置与工作目录。

### 开发脚本与测试配置位置

- `scripts/pi-check.mjs`：手动检查模型连通性。在项目根目录执行 `node --env-file=.env scripts/pi-check.mjs`，会发送一次真实模型请求；不属于离线检查或应用启动流程。
- `config/playwright.ui.config.cjs`：Playwright UI 测试配置，由 `scripts/run-ui-case.cjs` 指定加载；用例仍位于项目根目录下的 `qa/ui/cases/`，执行入口仍为 `QA_TARGET_URL="页面地址" npm run ui:case -- <case-id>`。

### 用例设计效果验收

继续使用本仓库受信任会话，确认资源列表包含 `qa-case-design`。下面是独立的虚构业务需求，仅用于验收技能输出，不代表本项目已实现上传功能。发送：

```text
/skill:qa-case-design 请依据以下需求设计测试用例，仅在回复中输出。
R1：只有已登录用户可上传文件；未登录时显示“请先登录”，不提交上传。
R2：一次只能选择一个文件，仅允许扩展名为 .pdf 或 .png 的文件。
R3：文件大小必须为 1 至 10485760 字节，包含两端；不满足类型或大小限制时显示校验失败，不提交上传。
R4：服务器确认上传成功后显示“上传成功”和文件名；服务器返回失败时显示“上传失败”，保留当前文件供用户手动重试，不自动重试。
请先列风险，再输出含需求编号来源的用例表；未规定的行为列为待确认项，不补造确定预期。
```

通过标准：

- 工具记录可核对读取 `.pi/skills/qa-case-design/references/case-format.md`；仅有格式相似的回复不证明实际读取。
- 先列风险；表格包含编号、来源、风险项、前置条件、操作或输入、可判定预期、执行状态，来源可追溯到 R1–R4。
- 覆盖登录状态、允许与不允许的类型、多文件选择、0/1/10485760/10485761 字节，以及成功、失败、手动重试与不自动重试。
- 扩展名大小写、内容与扩展名不符、超时、重复上传及并发处理等未规定行为列为待确认项；不擅自给出业务结论或错误提示原文。
- 所有用例标为“未执行”，不运行脚本、不修改被测代码、不生成文件。需求设计输出不等于测试执行或上传功能验收通过。

本步骤使用官方显式技能命令验证输出。2026-11-03 使用者反馈用例设计的实际模型效果已验收；此反馈不代表自然语言自动选择或被测功能的测试执行已通过。

### 自然语言选择验收

按固定版本官方 [Skills 文档](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/skills.md)，Pi 将技能名称、描述和路径加入系统提示词，由模型按任务读取完整 SKILL.md；自动选择可能遗漏，显式 `/skill:name` 是官方提供的强制加载方式。本步骤不新增宿主关键词路由或预加载所有技能正文。

在本仓库受信任目录下分别新建两个会话，不复用已展开技能的会话，不在请求中写技能名或技能路径：

核对工具记录：A 应读取 `qa-requirement-review/SKILL.md` 及其 `references/checklist.md`；B 应读取 `qa-case-design/SKILL.md` 及其 `references/case-format.md`。路径均位于本项目 `.pi/skills/`。同时按前述两类技能的输出要求检查内容，不能仅凭模型自称使用技能或回复格式相似判定加载成功。

`qa-skill-smoke` 设置了 `disable-model-invocation: true`，应不出现在自动匹配的技能目录中；本次两类请求也不应调用它。该设置隐藏自动选择目录，不是禁止工具读取文件的权限边界。

## 工具与文件状态

不传入自定义工具允许名单或替代 read。默认启用 read、bash、edit、write，尊重 `defaultTools`；扩展工具也遵循 Pi 登记及启用语义。edit 的参数为 `path` 和 `edits: [{ oldText, newText }]`。

原生 edit/write 和命令可直接改动文件，成功后不再等待草稿保存。工作目录是相对路径基准，不限制绝对路径或命令的访问范围。旧草稿的存储、审阅和历史记录仍可使用，其限制不适用于原生工具。

模型与凭据改由官方 ModelRuntime 读取 models.json、auth.json 和环境变量；Provider 扩展按公开登记 API 接入。新对话优先 Pi 设置中的默认模型，.env 仅作后备；恢复时使用历史登记的供应商和模型。会话仍通过 sessionManager 使用应用的真实目录绑定与历史。原私有模型配置、凭据服务与 OAuth 页面已移除，详见 [模型与供应商](model-management.md)。

## 斜杠命令

输入框以 `/` 开头时展开命令菜单，列出桌面内置命令与当前会话已加载的资源命令（`扩展`、`模板`、`技能`）。资源命令来自 SDK 已登记的扩展命令、提示词模板和技能，菜单只显示名称、参数提示、说明和来源，不读取技能正文或扩展实现。

内置命令为 `/new`、`/compact [说明]`、`/export`、`/reload`、`/session`、`/model [供应商/模型]`、`/thinking [等级]`、`/name [名称]`，复用页面已有按钮和主进程接口，不进入模型对话；与资源命令同名时保留内置语义。资源命令选中后仍走原有发送链路，由 SDK 展开技能和模板。

键盘焦点留在输入框：`↑`/`↓` 在列表首尾循环选择，`Tab` 补全，`Esc` 关闭；命令名未输入完整时 `Enter` 只补全，已完整输入时 `Enter` 直接执行。选中项在列表内滚动，只移动菜单自身，不带动输入区和消息区。菜单与输入法的组词状态互不干扰，焦点离开输入框时收起。命令列表在首次打开和会话变化时读取，读取失败回退为内置命令并提示，不影响发送。

鼠标悬停与键盘选择互不夺取：指针真正移动（超过 4px）才把选中项交给悬停行，指针静止或列表滚动产生的 `mousemove` 不会打断方向键。悬停只是浅底色，键盘选中另加左侧强调条，两者同时出现时也能分辨当前选中项。

菜单按中文展示：命令名保持原样（它是实际输入内容），下一行显示中文名称，说明列显示中文说明；未收录的条目继续显示资源自带原文，不会出现空白说明。翻译只是渲染层的对照表，命令执行仍用原始名称，不改变 SDK 展开、技能调用或扩展行为。中文说明被替换时，悬停可看到资源原始说明便于核对；资源自带中文说明（如多数技能）则原样保留，不做二次改写。中文名称也参与筛选：输入中文按包含匹配，输入英文仍按前缀匹配，避免无关结果；选中后填入的仍是原始命令名。

`/reload` 与 `session.desktopReloadResources` 共用同一份重载逻辑，经空闲互斥执行，成功后页面显示“Pi 资源已重新加载。”；后续打开菜单会重新读取资源命令。

## 信任与扩展

项目信任按官方顺序处理：用户扩展 project_trust 事件、最近保存的目录决定、全局默认策略、桌面确认。拒绝时由官方 loader 跳过受保护的项目资源；上下文文件不属于此保护范围。信任不会限制工具、扩展或安装器的进程权限。

内置 codemode、tool-search 和 MCP 通过公开工厂登记，支持其官方 builtin 配置和替换行为。会话调用 bindExtensions 启动运行时；切换或关闭时等待 session_shutdown 与设置保存后再 dispose。输入保存失败或会话清理失败时保留窗口。

`/reload` 调用官方 session.reload，不请求模型，并与聊天发送及其他主进程操作互斥。成功后页面保留“Pi 资源已重新加载。”，不会被普通回复结束提示覆盖；具体技能是否加载需在资源列表核对。扩展 ctx.reload 接入同一重载函数。加载诊断和运行事件错误分别报告。

桌面通过 `bindExtensions({ mode: "rpc", uiContext, commandContextActions })` 绑定，`hasUI=true`；无界面检查仍使用 json/hasUI=false。选择、确认、输入支持信号取消和超时，多行编辑支持预填；通知、状态、字符串数组组件、标题、编辑器正文与工具展开接入页面。正文等输入绑定完成且组词结束后经原保存链路应用，页面销毁/重载会结束等待，迟到响应不再消费。

继承官方默认非 TUI UI context；自定义终端组件返回 undefined，终端编辑器、输入监听、页眉页脚、工作指示器与主题切换等不支持的方法维持官方非 TUI 行为。Pi 终端主题不会自动转换为 CSS。不要仅凭 hasUI 判断 TUI 组件可用，应结合 mode。

`waitForIdle/newSession/fork/navigateTree/switchSession/reload` 通过公开 SDK 执行。`AgentSessionRuntime` 负责真实会话替换和 withSession；宿主重绑事件、输入与停止目标，仍检查应用历史归属和归档状态。官方替换先释放旧会话；创建失败明确提示重新打开，setup/withSession 在替换后失败时继续跟随实际新对象，不虚构回滚。显式 display=true 的扩展自定义消息按纯文本展示并恢复。

## 包管理

设置 → 技能与扩展包，展示当前会话资源及诊断。技能/模板按钮只把官方命令插入输入框，供使用者检查后发送。

界面按技能、提示词模板、扩展、扩展包四类展示，并提供当前目录、项目信任与数量。技能和模板使用卡片，扩展按需展开路径；包安装单独收起，包列表区分个人/项目、已安装/未安装和筛选状态。资源筛选使用官方 JSON，移除可确认或取消，诊断按级别和来源折叠展示。安装及筛选后的“待应用”提示只有成功重载才清除；刷新列表不会代替重载。未信任项目的包操作在页面禁用，主进程仍按原契约校验。界面只读取当前会话已经加载的资源，不把已登记的包冒充为已加载能力。

布局沿用现有设置导航和原生 DOM，样式独立放在 `src/renderer/styles/pi-resources.css`，颜色使用应用主题变量。依据固定版本的 [Skills](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/skills.md)、[Extensions](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/extensions.md) 与 [Packages](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/packages.md)；不改变官方安装、项目范围、过滤和重载行为。

技能中文名称与资源说明译文统一归类在 `pi-resource-translations.js`，覆盖当前安装的项目技能、Playwright、Postman、MCP、子智能体、达尔文及钉钉技能，以及子智能体模板。设置卡片、操作确认与无障碍名称显示中文；输入框命令菜单共用技能译名和描述，支持按中文名检索，插入时仍使用原始 `/skill:名称`。名称按技能标识匹配，描述按原文匹配，只用于显示，不修改第三方文件、模型读取的描述或命令。已有中文描述保留，混合描述中的 `Use when` 显示为“适用于”；新增或变更后未收录的名称和描述保留原文，不以泛化中文冒充翻译，也不请求模型或外部翻译服务。已知加载诊断提供中文说明，未知错误保留原始排错信息。扩展标题采用入口所属目录名称，单文件扩展去掉脚本后缀；编译目录入口优先采用 Pi 登记的 npm 包名，内置及已知扩展显示中文名称与用途。完整路径仍可展开查看。

通过公开 `DefaultPackageManager` 执行 npm、Git、本地来源的安装、更新、移除和更新检查；本地包按标准目录或可选 pi 清单发现，不要求 pi-package 关键词。个人与项目范围由官方设置保存，项目范围需先信任。资源筛选直接使用官方 `extensions/skills/prompts/themes` 字符串数组和 `autoload` 布尔值；空数组禁用该类资源，空对象恢复默认发现。

安装来源可直接填写 `npm:billion-context`，也可粘贴 `pi install npm:billion-context`。桌面仅从命令提取单个来源并交给官方安装器，不执行命令文本；含空格的本地路径在命令中需加引号，直接填写路径时无需引号。范围由页面选择；多个来源或额外命令参数会在安装前提示修正。

卸载遵循 Pi 1.4.0 的 [`pi remove` / `pi uninstall`](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/cli.md#package-commands)：扩展包列表提供“卸载”，包内技能、模板和扩展根据官方 `sourceInfo` 的 `origin/source/scope` 展示“卸载所属包”，不按名称或文件路径猜测归属。确认前展示整包影响和个人/当前项目范围；后台先核对当前登记与项目信任，再调用公开 `DefaultPackageManager.removeAndPersist(source, { local })`，检查返回值并保存设置。npm 卸载交给官方配置的包管理器，Git 删除对应安装副本，本地来源只取消配置、保留源文件；其他范围登记保持不变，重载时可能重新出现同名资源。未安装但已登记的包也可卸载配置。未登记、临时来源、独立发现的技能和内置扩展不提供包卸载按钮；独立资源在原目录管理，内置扩展通过 Pi 配置启用或禁用，不删除系统或用户资源文件。

卸载成功后保留“待重载”提示，当前会话已加载资源仍展示到显式重载；所属包已不在配置中的资源不再提供重复卸载入口。卸载失败保留错误与刷新/重试入口，不宣称事务回滚。专项验证入口为 `node --require ./tests/helpers/pi-test-isolation.cjs --test tests/unit/pi-package-service.test.js`、`node_modules/.bin/electron tests/ui/pi-resources-page.check.cjs` 和 `node_modules/.bin/electron tests/ui/pi-desktop.check.cjs`：分别覆盖卸载范围、官方离线 npm 与临时 Git 安装副本、来源关联、错误/信任/重复操作，以及本地包源文件保留和重载。使用临时配置与资源，不卸载使用者真实已安装的包，不将临时 Git 副本检查扩大为远程下载验收。

只是不需要某个技能时，技能卡片提供“停用此技能”。这是官方 `pi config` 的单项资源排除语义：包内技能在所属包 `skills` 筛选中写入 `-相对文件路径`，独立技能在对应个人或项目 `skills` 中写入精确的绝对路径排除项，以适配 `.pi` 与祖先 `.agents/skills` 的不同基准。主进程只接受当前会话已加载技能的真实路径，重新核对来源和范围，保留其他筛选、模板与扩展配置，使用公开 SettingsManager 保存；不删除文件、不卸载整包。停用待重载时禁止重复操作和插入该技能命令；成功重载后从可用技能列表消失。需要恢复时可在 Pi 官方资源配置中重新启用，或移除对应精确排除项后重载。临时真实 loader 检查覆盖包内兄弟技能、独立技能、项目 `.pi` 和 `.agents` 技能、范围与信任校验及重建加载持久化。

安装/筛选/更新后显式重载才应用到当前会话，不自动激活新扩展。`update(source)` 的实际范围遵循官方 API，同一来源同时配置在个人与项目时可能一并更新；范围选择不是更新隔离。安装器可能执行代码；SDK 没有取消或事务回滚契约，失败会明确提示核对磁盘与登记，不承诺还原。
