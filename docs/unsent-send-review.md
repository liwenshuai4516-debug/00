# 无历史待确认发送：查看与显式清理

当应用保存了发送快照，但无法确认请求是否已被处理，且没有可打开的历史时，侧栏条目保留阻塞提示。现在可点击“查看待确认发送”，核对完整发送原文及另存的未发送输入，不需要先重建会话。

这是应用输入状态的处理入口，沿用 Pi 官方会话及历史格式，不改写原生工具、技能或模型行为。

## 使用方式

1. 重启应用以加载宿主代码。在原项目中找到带“仍有待确认发送”提示的条目，点击“查看待确认发送”。
2. 只读核对发送原文和另存输入，需要保留的内容先手动复制。查看不切换当前对话，不把快照填回消息框。
3. 点击“清理这份快照…”只展开说明；选择“取消清理”或关闭弹窗都不会清理。
4. 确定不再保留快照后，点击“确认清理快照”。清理不表示原请求成功或未成功，也不发送任何请求。
5. 有另存输入时，条目解除限制，可再通过原入口恢复并核对输入；没有另存输入时，条目不再显示，但状态登记仍保留。清理不会自动恢复会话。

若条目就是当前会话，查看按钮会展开输入区已有的待确认发送入口，继续沿用当前输入的核对与解除流程。

没有自然出现的受阻条目时，真实业务验收记为未执行；不通过强制结束、删除历史或额外调用模型制造异常。

## 保护与失败处理

- 主进程只接受会话编号和确认时的发送编号；目录、快照和模型来自已保存状态。
- 必须属于当前真实工作目录，未归档，有可信 empty 来源及待确认快照；实际历史或内存中已有消息时拒绝本专用入口。
- 查看和清理共用 `runIdleOperation`，与生成、整理、会话切换等互斥。输入保存、停止和取消仍走各自原入口。
- 清理在状态存储的串行更新中重查来源、归档和发送编号，只移除匹配的 `pendingSend`；草稿原文与版本、模型、提示词和组织字段保留。
- 读取失败不能清理。快照变化、写入失败或返回丢失后，页面禁用旧确认，要求“重新核对”，不自动重试清理。
- 原文和目录通过 `textContent` 展示；弹窗支持键盘关闭、取消与焦点返回，窄窗内容可滚动。
