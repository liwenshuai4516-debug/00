# 日常使用体验设计

状态（2026-11-02）：输入恢复与关闭保存、置顶与可撤销归档、上下文用量常驻入口均已接通。上下文本轮实际与精确提交副本62项单元及122项页面检查通过，见`docs/context-usage.md`；未读取真实会话或请求模型，尚无本轮真实用量验收反馈。使用者已授权助手直接实施代码；下一步为项目重命名完整接线。下文阶段记录保留，当前进度以本段和AGENTS.md最新交接为准。

## 目标与当前基础

三项功能按“输入草稿重启恢复 → 会话置顶与归档 → 上下文用量常驻展示”推进，共用轻量会话状态存储。沿用原生 DOM、现有深色主题、会话侧栏、底部输入区和受限预加载接口。

当前实际情况：

- 页面已使用composer-persistence接入按会话保存、版本发送和异常核对；未发送空会话重建与关闭补保存已完成。关闭接线实际与精确副本119项单元及14+19+27项页面检查通过，使用者另反馈完成关窗与重启必做验收；可选场景没有逐项反馈。
- 会话侧栏按真实工作目录分组、按标题搜索，组内置顶优先并保留稳定排序，组间仍按消息活动排列；置顶及归档视图、恢复、撤销已接通。存储已有pinnedAt/archivedAt字段，组织操作不改消息活动时间。
- `getSessionInfo()`的一次读取同时更新菜单信息和输入区常驻用量，详情支持重读及主动整理；保留未知估算语义和会话/模型迟到响应保护，不新增模型查询接口。
- Pi 1.4.0 在出现 user/assistant 消息前不创建历史文件。不能只扫描历史文件实现未发送输入的恢复。
- 项目打开仍按最近有消息活动的合法且未归档对话恢复；此规则不因自动保存输入或置顶而改变。

成功标准：草稿严格归属原会话和工作目录；发送成功不再恢复已发送输入；生成期间写的新输入能恢复；归档可长期找回，不删除或移动原记录；上下文状态易发现且不把未知值当作零。

## 一、输入草稿重启恢复

### 使用体验

- 自动保存输入原文，保留首尾空格、缩进、空行和混合换行；不能 trim 后存储。
- 输入区下方显示“正在保存输入…”、“输入已保存”或“输入未保存，重试”。这与“文件草稿”按钮分开，避免混淆。
- 输入变化后约 300 ms 保存；持续输入最长约 1 秒执行一次保存。切换会话、项目及正常关闭窗口时补齐待保存内容。
- 状态仅在主进程确认写入后显示已保存。强制结束进程只保证已确认落盘的内容，不能宣称尚未确认的最后字符也已保存。
- 初次加载或异步读取草稿期间，用户已输入的文字优先；任何迟到读取都不能覆盖正在编辑的内容。
- 同一会话内刷新历史、重命名或刷新模型，不重新填充输入框。

### 会话隔离与版本

每次编辑、读取和保存都捕获明确的 `sessionId`，主进程从可信登记取得工作目录，不接受页面提交任意路径。切换等待期间的新输入仍属于原会话；切换成功后，原会话待写内容仍以原编号保存。

每条草稿保存版本号。页面对同一会话只保留一个在途保存，合并后续编辑；主进程对同一会话的状态更新串行执行，并检查预期版本。旧写入不能覆盖发送后清空的新版本，也不能覆盖用户后来写入或主动清空的版本。发生版本冲突时重新协调当前编辑，不盲目重试旧正文。

恢复读取同时校验当前会话编号和页面编辑序号：A 的读取晚于切到 B 返回时，不能写进 B 的输入框。空字符串代表明确清空，与“没有记录”区分。

### 发送时的行为

发送入口需要与主进程草稿版本关联，不能仅在页面最终清空磁盘文本。

| 时点或结果 | 持久化与页面行为 |
| --- | --- |
| 点击发送 | 固定原文、会话编号、被消费的草稿版本和发送编号；主进程先保存发送快照及草稿已消费状态，再进入模型调用 |
| 等待主进程确认 | 新输入先留在页面缓冲；收到本次消费后的版本确认，再按新版本保存，不允许旧自动保存覆盖空状态 |
| 生成期间继续输入 | 新输入属于同一会话的新草稿版本，独立保存 |
| 正常回复完成或主动停止 | 主进程结束本次发送快照；只处理被消费的版本，保留后来的输入 |
| 明确请求失败 | 没有后续编辑且输入仍为空时恢复原文并保存；存在新输入或后来明确清空时，保留用户的新版本 |
| 回复已经完成，仅列表或信息刷新失败 | 仍按发送已完成处理，不恢复原文 |
| 模型调用前的消费状态写入失败 | 不发送请求；保留输入并提示写入失败 |
| 模型已完成，但收尾状态写入失败 | 返回请求已完成并附保存状态提示，不能把它变成可恢复旧输入的请求失败 |
| 发送中应用退出或进程崩溃 | 普通输入框只恢复最新未发送草稿；未确认发送快照单独提供“查看/复制原文”，不自动回填、不自动重发 |

发送状态在主进程收尾，不能依赖页面一直存活。单独保留结果未确认的发送快照，解决“模型已处理，但界面未收到完成”的窗口；本阶段不承诺远端模型请求恰好执行一次。

### 尚未发送过消息的新会话

- 首次保存输入时，主进程登记该空会话的原编号、真实目录和所选模型；不向聊天历史追加虚构消息来强制落盘。
- 这类记录在对应目录组内以“未发送”入口展示。草稿为空且没有真实历史时，不保留空白条目。
- 点击入口时先查是否已有同编号的真实历史；有则走既有绑定检查和恢复链路，不能新建覆盖它。
- 确认属于尚未落盘的新会话后，使用公开的 `SessionManager.create(cwd, sessionDir, { id })` 重建同编号空会话，补回应用绑定并恢复已登记模型，再关联原草稿。
- 对已经存在过的历史会话，原文件缺失时只保留输入并提示无法打开，不将其当作空会话重建。
- 目录失效、绑定不匹配或模型未登记时明确失败并保留草稿；不静默恢复到其他目录或其他会话。
- 不改变项目恢复“最近消息活动”的规则。未发送入口可找回其输入，不把输入自动挪给启动时默认恢复的对话。

已通过临时 SDK 检查：指定原编号可重建空会话，单独添加目录绑定不会落盘聊天历史；未请求模型。完整草稿恢复流程仍待实施验证。

## 二、会话置顶与归档

### 置顶

- 每条已有历史对话右侧提供独立“对话操作”菜单，内含“置顶/取消置顶”“归档”。不把菜单按钮嵌入打开对话的按钮内。
- 置顶只在原目录组内提前显示，保留标题和明确的置顶标记。
- 多条置顶按置顶时间从新到旧排列；普通会话继续按消息活动排列；并列时按稳定编号排序，避免列表跳动。
- 置顶、归档和输入自动保存不更新会话消息活动时间，不改变项目自动恢复目标。
- “未发送”草稿入口先只承担恢复输入；第一版置顶与归档作用于已有历史会话。

### 归档与恢复

- 侧栏在搜索附近提供“对话 / 已归档”切换。普通列表不显示归档项；已归档列表支持同样的目录分组和标题搜索。
- 归档仅写入应用状态，不删除、移动或改写 Pi 历史文件，也不移除输入草稿、模型选择、工作目录绑定和未保存文件草稿。
- 成功后显示“已归档该对话 · 撤销”。撤销提示暂留约 8 秒，键盘聚焦或指针停留时暂停消失；无论提示是否消失，已归档列表都提供“恢复”。
- 恢复只修改归档标记，保留原编号、原记录和原置顶信息；不自动切换当前对话，避免打断正在输入的新内容。
- 归档非当前会话只更新列表。归档当前会话时，先保存输入并准备当前目录的新空会话，归档落盘成功后才切换；准备或写入失败时保留原会话和归档状态。
- 已归档列表的查看动作复用只读历史预览，不隐式打开成可发送会话；恢复后用户再选择继续对话。
- 生成、整理上下文、保存文件或切换期间，置顶、归档与恢复共用现有主进程互斥入口。

### 自动恢复必须同步修改

启动恢复和打开其他项目时，选择最近合法会话必须跳过归档项；全部归档时创建新会话。当前项目重复点击仍保留当前对话。过滤归档状态之后，继续执行现有工作目录和应用绑定检查。

不能只让侧栏过滤归档项，否则 SDK 自动恢复仍可能重新打开它们。应用状态读取失败时明确报错，不把所有归档标记默认为未归档；修复、恢复、新建入口保留原数据。

列表加入操作按钮后，`page-shell.js` 的侧栏收起事件必须只响应“打开对话”，不能让点击置顶菜单或归档按钮也收起侧栏。选中项及顶部标题仍由打开按钮维护。

## 三、上下文用量更易发现

### 页面入口

输入区底部的提示行左侧继续显示键盘提示，右侧常驻“上下文约 32%”按钮。窄窗口允许该行换行，不挤压发送按钮和模型选择。

点击或键盘激活后展开详情，展示估算 tokens、模型窗口大小及解释；提供现有“整理上下文”入口。整理只由用户主动点击触发，保持已有取消与忙碌约束。

| 状态 | 常驻入口与详情 |
| --- | --- |
| 有正常估算 | “上下文约 32%”；详情显示当前估算与窗口大小 |
| 低于 75% | 使用普通中性色 |
| 达到 75% | 显示“用量较高”及文字提醒 |
| 达到 90% | 显示“接近上限”，提供整理入口；不据此禁止发送 |
| SDK 暂无估算 | “上下文待估算”，不能显示 0% |
| 上下文整理后暂时未知 | “等待后续回复更新估算”，保留已知窗口大小 |
| 读取失败 | “上下文读取失败”，提供重试；不能继续展示另一会话的数字 |
| 正在生成 | 可以保留同一会话上次估算，但明确“生成中，显示上次估算” |

75% 与 90% 是产品提示阈值，不代表 SDK 保证在该比例整理、请求一定成功或一定失败。上下文估算不是费用、账号配额或全部原始历史总量。

### 数据与刷新

复用 `getSessionInfo().contextUsage`，由同一份读取结果更新详情和常驻入口，避免为了两个展示位置重复查询。保留现有未知值语义。

刷新时机：首次加载、新建/打开会话、打开项目、工作目录切换、模型切换、发送结束（含停止与失败）、整理结束/取消，以及文件保存事实加入会话后。第一版不按 token 轮询，也不增加模型请求。

切换目标或模型时立即将旧数字改为加载状态；响应须匹配会话编号及本次刷新序号，防止迟到结果覆盖新会话或新模型。状态播报使用一个带上下文的温和状态区域，不逐 token 宣读，也不与现有会话详情重复播报。

| 用量展示 | session-info-panel 复用格式化和统一数据读取；新增或拆出轻量上下文入口组件，样式沿用现有主题变量 |
| 窗口生命周期 | 正常关闭前握手等待待写输入，不能只在 closed 或 beforeunload 里临时发异步保存；关闭后继续执行现有停止逻辑 |

输入保存需要在生成期间可用，不能直接套用会阻止生成期间操作的 `runIdleOperation`。组织动作继续走现有互斥入口；两个入口都通过同一个状态存储保证写入顺序。

## 五、手写实施与验收顺序

1. **会话状态存储（已完成）**：实际模块与8项临时文件测试通过，覆盖原文往返、空串、版本冲突、同会话并发更新、写入失败和损坏文件保留。尚未接页面或发送流程。
2. **输入恢复**：服务、受限接口、空会话登记与 SDK 恢复、页面保存队列、发送消费与收尾、正常关闭补保存；完成后才称支持重启恢复。
3. **置顶与归档**：先补服务及启动/项目恢复过滤，再做侧栏菜单、归档视图、撤销及当前会话归档切换。
4. **上下文入口**：复用现有信息接口，统一刷新后接常驻按钮和详情，检查窄窗口、键盘及未知状态。

核心验收：

- A/B 会话及不同项目输入分别保存，重启后打开各自恢复；新建且未发送过消息的输入也可找回；迟到读取或保存不能串会话。
- 首尾空白、Tab、换行、用户主动清空均准确；保存失败不显示已保存；正常关闭补齐待写输入。
- 发送成功或主动停止后重启不回填已消费输入；回复后列表失败也不恢复；生成期间的新输入单独恢复。
- 明确请求失败时保留原文恢复能力，又不覆盖等待期间的新输入；发送结果未确认时只提供手动查看，不自动重发。
- 置顶重启保留；归档后普通列表隐藏，撤销或重启后从已归档列表恢复；原历史文件字节和原编号不变，输入与文件草稿仍在。
- 启动、项目打开及全部归档情形都不自动恢复归档对话；归档当前会话失败时当前对话和输入不变；撤销不打断新输入。
- 上下文正常、有效零值、未知、整理后未知、读取失败及模型变化均准确；跨会话迟到响应不覆盖，窄窗口无整页横向溢出。

仅运行每步影响的测试，使用临时目录和模拟服务。未请求真实模型的检查不能替代真实界面验收，也不读取用户真实会话、输入草稿或密钥。
