# 下一步：正常关闭与重启恢复验收

本页用于使用者真实界面验收，不需要再修改应用代码。正常关闭握手已由使用者接通；自动检查通过不代替真实系统窗口、输入法和重启验收。

## 本轮已验证的范围

实际工作区已通过12个脚本语法检查、15个相关测试文件119项，以及实际Electron关闭页面14项、未发送页面19项、侧栏27项检查。检查使用临时userData、本地模拟接口，不读取真实.env、配置/会话，不请求模型或写入工作文件。关闭失败、停止失败、旧会话失败输入重试和重复关闭由模拟接口验证。

完整验证命令继续见`docs/window-close-integration-step.md`第10节。本轮手写功能已经接通，不再按该指南重复实施。

## 1. 准备

在项目目录运行：

```bash
npm start
```

“关闭窗口”指点击窗口左上角红色关闭按钮；“彻底退出”指应用获得焦点后按Command+Q，并等本次启动的终端返回命令提示。不要用终端Control+C或活动监视器强制结束代替正常退出。

macOS普通关窗后进程继续运行是正常行为。可点击Dock中的图标重新开窗；普通关窗与彻底退出需要分别验收。

## 2. 必做的三组检查

每组都使用你自己的普通输入，不发送给模型。不要只核对文本摘要，应打开对应对话看完整输入。

| 检查 | 操作 | 通过标准 |
| --- | --- | --- |
| 最后编辑和主动清空 | 在已有会话输入`关闭验收：最后一段中文`，换行再写一行，输入法组词结束后立即点红色关闭；重新开窗并打开原会话。随后主动清空输入，再立即关窗、重新打开原会话。 | 第一次完整恢复两行；第二次仍为空，不恢复旧文字。 |
| 两个会话分别保留 | 在两个已有会话分别输入`A会话待发送`和`B会话待发送`，切换后核对没有串输入；按Command+Q彻底退出，再npm start并分别打开。 | 两个输入各归原会话；Command+Q后终端返回，新启动后仍分别恢复。 |
| 未发送空会话 | 记下原工作目录；新建对话，输入`未发送空会话恢复`且不发送，立即Command+Q；重新启动，在同一目录的“未发送”列表恢复该条目。若列表暂未更新，点刷新一次。 | 能恢复完整输入；保留这个空会话的原模型选择，不额外创建一份不同编号的重复对话。 |

第三组可沿用已有模型选择，无需为验收新建或修改模型配置。如果列表缺失、条目受阻或恢复失败，记录页面提示和操作顺序，不清理本地状态文件。

如果原会话已有待保存文件草稿，顺便核对关窗和重开后仍可查看。这里的“保存输入”不会替你确认保存文件草稿。

## 3. 按现有使用场景补充

| 场景 | 通过标准 |
| --- | --- |
| 正常使用中已经有生成正在进行 | 生成期间输入一段新的未发送文字，再关窗或退出；应先停止并等待收尾，重开后保留新输入，不恢复已经消费的发送原文。 |
| 正常使用中已经在整理上下文 | 关闭应取消整理并等原操作收尾，重开后保留原输入和文件草稿。 |
| 目录选择或导出系统窗口已打开 | 先完成或取消系统窗口；原操作结束后再完成关闭保存，不跳过在途操作。 |
| 中文输入法仍在组词时点击关闭 | 观察是否能结束组词并关闭，重开后核对最后中文。若一直停在“正在准备关闭”，记录此状态；不能把模拟composition事件通过当成真实输入法已经通过。 |

没有合适场景的项目记为“未验收”，无需额外发起付费请求。磁盘和停止故障已有自动模拟覆盖，不需要破坏真实配置、删除会话文件或故意制造线上失败。
