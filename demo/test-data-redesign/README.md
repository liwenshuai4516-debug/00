## 运行

方式一，直接双击打开 `index.html`。

方式二，起一个本地静态服务（推荐，浏览器对 `localStorage` 的限制最少）：

```bash
cd demo/test-data-redesign
python3 -m http.server 4173
# 浏览器打开 http://127.0.0.1:4173/
```

## 本版对应你的四点要求

1. **目录与用例左右布局**：左侧 292px 目录树，右侧用例工作区；目录支持折叠、筛选、选中，父目录会汇总所有下级用例。
2. **去掉「其他测试数据」**：本版完全不展示 `qa/data` 文件列表，也不再放「删除文件」入口。
3. **用例持久化增删改查**：新增、编辑、删除、按目录移动、状态/优先级/版本号/步骤/预期结果都会写入浏览器 `localStorage`，刷新后保留。演示数据 key 为 `swqa.test-data.demo.v1`。
4. **先交付 Demo**：只新增 `demo/test-data-redesign/`，不改动现有应用页面和 IPC；确认设计后再接正式数据层。

## 已实现的交互

- 新建用例：标题、目录、执行角色、状态、优先级、版本号、说明、执行步骤、预期结果。
- 编辑用例：复用同一表单，支持调整目录；保存后自动定位到新目录。
- 删除用例：二次确认，删除后目录计数、状态统计、列表同步更新。
- 新建目录：支持 `合同管理/补充协议` 这种多级路径，空目录也会保留。
- 检索与筛选：按标题、说明、角色、目录搜索；按正式/候选/草稿过滤；最近更新/优先级/标题排序。
- 详情抽屉：查看元信息、步骤和预期结果，可直接编辑或删除。
- 辅助能力：`⌘K` / `Ctrl K` 聚焦搜索、`Esc` 关闭弹层、浅色/深色主题切换、重置示例数据。

## Demo 的边界

- 数据存在浏览器 `localStorage`，不是 `qa/ui/cases` 磁盘资产，也没有多窗口并发合并。
- 只演示单项目、单页列表；未实现分页、版本历史、真实回归结果、执行入口和权限校验。
- 状态里的「最近通过/失败」是随示例数据写入的静态展示，不代表真实测试运行。
- 正式接入时建议映射到现有 `test-data-service`：列表接口补 `create/update/delete/move`，目录组织继续复用 `folder` / `modulePath`，页面布局直接替换右侧栏的 `renderCaseCatalog`。

## 验证

已用 Playwright Chromium 在 `1440×900`、`1024×768`、`700×900` 下检查布局，并跑通：

- 初始 10 条示例用例渲染与统计；
- 搜索、状态筛选、目录切换；
- 新建 → 刷新保留 → 编辑 → 刷新保留 → 删除 → 刷新消失；
- 新建目录、写入 `localStorage`、重置示例；
- 详情抽屉、编辑弹窗、浅色主题切换；
- 页面无 console error / page error。
