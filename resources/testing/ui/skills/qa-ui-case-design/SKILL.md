# UI 用例生成规则

本技能维护用例设计规则。只要求设计或检查粒度时不启动浏览器；需要探索和生成可执行候选时转 qa-ui-basic，按其工具契约执行，不扩大用户范围或执行权限。

## 覆盖与来源

生成前按用户指定范围建立覆盖清单，包含检查项编号、功能、输入条件、预期及来源、计划 caseId。已有设计稿逐项映射，不直接当成可执行脚本；遗漏、受阻和待确认项保留原因，不从清单删除。按范围内风险决定先后顺序，用一句话说明先测这一批的理由。

每条用例具备来源、前置条件、操作或输入、可判定预期，追溯到需求、风险或覆盖清单中的检查项。预期依据用户要求、明确页面规则或已确认基线，保留可定位引用；不以运行实际结果或模型猜测倒推预期。缺少会改变预期的业务口径时标为待确认，不猜造正确结果。

## 审批用例关联

用户范围涉及提交审批、审批节点、处理人、审批权限、可选分支或审批终态时，先加载实际测试工作区中已登记的 qa-approval-workflow，再生成对应审批 case；不能只生成列表、查询或表单入口 case 后把审批范围略去。该技能是项目资源，通常位于实际工作区 `.pi/skills/qa-approval-workflow/SKILL.md`，不使用客户端仓库的固定绝对路径。未登记或缺少参考文件时报告缺失，审批项保留为待确认，继续不依赖它的设计，不猜审批链或静默套用其他流程。

按该技能选择本次业务的准确流程模型与发起部门，读取对应完整链、人员基线及核实范围；用户本次提供的对照表优先。覆盖清单增加流程模型、发起部门、节点序号/角色、动作或分支、预期状态/下一处理人、来源与核实状态，并为范围内的独立检查项分配 caseId。角色名不等于登录账号；缺失人员、开关或未核实流程分别标为待确认，不借用历史案例补齐。

| 范围内的审批检查项 | 对应 case 设计 |
| --- | --- |
| 提交及节点流转 | 提交后进入首个节点；各节点已定义动作后的下一节点、处理人和状态，分别成例 |
| 审批角色与权限 | 当前处理人可见并可用的动作；非当前处理人的访问或操作限制，依据已确认权限规则分别成例 |
| 可选节点与流程分支 | 有来源的启用、跳过及路由条件分别成例；拒绝、退回、撤回仅在需求或配置已定义且属于本次范围时生成 |
| 节点专属材料与操作 | 对应流程要求的定稿、终稿、盖章、确认或归档各自成例；有规则依据的缺失材料校验另成例，不把合同特例套到采购或立项 |
| 终态 | 对应流程的列表/详情完成状态、实际启用节点记录及必要附件或归档结果，不以到达最后节点代替终态断言 |

按用户范围和实际流程推导数量，不默认展开全部模型、部门或不存在的分支。同人连续出现仍按节点序号分别追溯。每例独立准备处于目标节点的专属记录及角色身份，不依赖前一条审批 case 留下状态；无法准备时标为执行受阻。仅明确要求的完整审批链另列 E2E。

只要求设计时生成上述用例说明与覆盖映射，不创建业务记录、不提交或审批。缺执行能力不等于缺设计范围：多角色审批目前不能交给 qa-ui-basic 自动执行，保留已设计用例并说明受阻，不伪造成功轨迹、候选或通过结果；实际执行仍须满足 qa-approval-workflow 的能力和授权边界。

## 单目标粒度

一条 case 只验证一个独立业务目标及一种输入条件。一个 Playwright test、一个页面或一次探索不天然等于一个独立业务目标；不把断言数当作用例数。

| 合并场景 | 拆分方式 |
| --- | --- |
| 合同编号命中、无结果、重置 | 编号命中；编号无结果；带编号筛选后重置 |
| 合同名称命中、无结果、重置 | 名称命中；名称无结果；带名称筛选后重置 |
| 表头、统计卡和发起入口 | 列表表头结构；统计卡标签与单位；发起入口可达 |
| 上一页、下一页、查询后页码恢复 | 上一页；下一页；查询后的页码行为 |

同一目标可以有多个必要断言。例如无结果查询同时检查总数为零、无数据行和空态；组合筛选验证条件交集也是一个目标。打开新建表单后检查必要字段与操作入口可以共同证明表单可达，不表示提交和必填校验已覆盖。只有用户明确要求端到端流程时才保留跨功能链，在标题与覆盖清单标为 E2E，不替代各功能独立用例。

## 独立执行

每例自行准备并核对身份、初态和数据，必须能单独运行、调换顺序，不依赖另一例的结果、残留业务数据、筛选、页码或浏览器状态。可使用共用登录准备，但业务初态仍由本例建立。登录、导航、必要数据准备和清理不增加业务测试目标；例如重置例先建立筛选状态，不附带验证命中和无结果两个目标。

写操作的数据隔离、唯一标识和清理按 qa-ui-basic 及实际授权执行；本技能不授予写入权限。

## 探索与候选衔接

生成可执行候选时，一次探索任务只对应一个独立用例目标和一种输入条件，在探索前冻结 expected。qa_ui_save_candidate 要求 case.expected 完整等于 task.contract.expected，每条预期都有业务断言。

发现已冻结任务混合多个目标时，保留原任务，回到覆盖清单拆分目标并分别取得真实探索证据；不删冻结预期、伪造轨迹、复制同一混合脚本改名凑数或改写已冻结版本。工具故障仍遵守原流程的停止与恢复规则，不把重新设计当成绕过故障的理由。

## 数量与交付检查

数量由独立覆盖项推导，不固定条数，不为凑数添加无来源场景。探索动作预算不决定用例数量。

交付前逐项核对单目标、独立初态与数据、预期来源和覆盖映射。分别记录已设计、已生成候选、已验证、已发布、受阻或待确认阶段及实际执行结果；候选不等于正式资产，受阻不计为已生成或通过。只完成部分范围时明确说明，不宣称整个页面或全部设计条目已完成。

静态保存和成功回放不能自动证明业务粒度或语义覆盖完整；这些仍须按本技能核对。失败、未执行与待确认项不得因其他用例通过而抹除。
